Calibrate

Set this up once per car before you start using the drive modes. Without it the controller only guesses how your Haldex responds, and an uncalibrated guess drives worse than leaving the car in Stock. Work top to bottom.

Checking calibration...
  1. Set your Generation to match the car.
  2. Run the Learn (engine running, car stationary, Haldex CAN live).
  3. Set Lock calibration to 1:1 using the learn chart.
  4. Optional: raise the Launch PWM floor.
  5. Not a TT Mk3? Check the Car geometry numbers (only affects the wheel slip readout).
  6. Still not smooth? Run Long Learn below, or edit the frame blocks by hand.

1 · Generation

Which Haldex controller is fitted to your car. This has to be right or nothing else works.

2 · Learn Haldex

Teaches the controller how your exact Haldex responds so lock commands hit their target. Engine running, car stationary, Haldex CAN connected. Takes a couple of minutes.

3 · Lock calibration

Lines up the lock you command with the lock the Haldex actually delivers. Run a Learn, then adjust this until the Sent vs Returned line sits on the 1:1 diagonal. Not a power dial.

4 · Launch PWM floor (experimental)

Optional. Holds a minimum clutch PWM under launch so engagement builds faster off the line. Leave at 0 unless you know you want it. Only applies while lock is commanded.

0 %

5 · Car geometry (optional)

Used only for the per-wheel slip readout on the Dashboard (how far each wheel is from the speed the steering says it should turn at). It does not change how the lock behaves. The defaults are for an Audi TT Mk3, so leave them alone for that car. For another car, take the numbers from its spec sheet or owner's manual (look under "Dimensions", "Track" and "Steering").

Long Learn

Advanced. Automates the add-a-block, remove-a-block loop for a learn that will not come out clean. It turns every frame block for this generation on, then (Gen5 0CQ / VAQ) steps the Launch PWM floor up until the learn is smooth. After that it removes the extra blocks one at a time: a block whose removal changes the learn goes back on (and is flagged if the learn was actually better without it), one that makes no difference stays off. A last confirmation learn is stored against the final set. Allow 10 to 20 minutes with the car running and Haldex CAN live. Cancelling puts back the old blocks, floor and learn table.

Off: your current set is kept and only the extra blocks are tested. On: every block is tested. That takes longer and can leave the Haldex with no lock command for part of a sweep.

Chassis / car notes

Free text kept on the module and written into the exported report: chassis, Haldex part number, tyres, tune, anything that identifies this car.

Frame blocks (advanced)

Turn editing of individual CAN frames on or off in normal (non-standalone) mode. A block that is off leaves the car's own frame untouched. Use it to find which edited frame upsets the learn. Changes apply at once and are saved. Only affects the selected generation.

Not available for this generation.

Brake / Handbrake Outputs

Drive the controller's brake/handbrake output pins from the matching input. "Follow" mirrors the input; "Invert" flips it (output active when the input is released). Leave off unless your wiring uses these pins.

Controller Options

Controller & Connectivity

Hard passthrough. The unit forwards every chassis frame to the Haldex untouched - no mode, no lock map, no overrides. The kill-switch when you want the car fully stock without unplugging.

For a car with no chassis CAN feeding the controller. It ignores incoming chassis frames and generates its own, so it can drive the Haldex on a bench or a stripped car. Stock mode is unavailable here (nothing to mirror).

Standalone only. Still read real chassis CAN (speed, throttle) when it is present, so Expert mode's speed/throttle map works instead of running blind.

Emit OpenHaldex status on the bus and accept mode-change commands from another OpenHaldex or external controller over CAN. Leave off if nothing else on the bus talks to it.

On a full 50:50 request, demands maximum clutch duty by leaving the Haldex no room to modulate. Most clamping force, but the Returned % will read lower (bench: about 99% pump duty and 10.5 A reporting in the 80s, against about 56% duty reporting about 98% with this off), because the Haldex backs its own estimate off once the pressure relief valve opens. Pump load and current draw go up a lot. Off by default.

Live Diagnostics

Polls the Haldex ECU for live data using whatever generation is set: Gen5 = UDS, Gen2/4 = KWP2000 over TP2.0. Requires Haldex CAN healthy.

Note: this takes over the diagnostic channel. Leave it OFF when using VCDS or another diagnostic tool.

Buttons

Low-Power Sleep

After 5 min idle with no WiFi clients and both CAN buses silent, sleep until a CAN frame arrives. The first wake frame may be lost.

Additionally parks the CAN transceivers in standby while sleeping, drops CPU floor to 10MHz, and lowers WiFi AP TX power. Bus activity wakes the transceivers via GPIO interrupt within microseconds; a 2s safety-net probe runs as backup.

Keeps the WiFi up for good while you bench test over USB with no harness connected, overriding CAN sleep above. It clears itself the moment real CAN traffic shows on either bus (once harnessed to a car), so it is safe to leave on - but switch it off when you finish tuning a permanent install.

WiFi Access Point

Name (SSID)

Change the access-point name broadcast by the controller. 1–32 printable ASCII characters. Saving restarts the AP — you will need to reconnect.

--

Password

Set a WPA2 password (min. 8 characters) to secure the access point. The access point always needs a password: saving restarts it and you reconnect with the new one. Forgotten it? Long-press the mode button on the unit - that clears the password and the setup page asks for a new one.

--

Home WiFi (Bridge Mode)

Optional: also join a home or garage WiFi as a client. The controller's own access point keeps running either way. This makes it reachable (and lets you update or back up) from a phone or laptop that is already on that network, with no WiFi switching. Leave it blank to turn it off. The controller still sleeps after 5 minutes without CAN traffic unless Bench Mode is on, and it only looks for the home network for 20 s after starting and then once every 5 minutes, so it cannot disturb the access point while you are away from home.

On the home network the module asks for a sign-in: user admin, password = your access-point WiFi password.

--

Bluetooth (DashCAN App)

Lets the DashCAN phone app show live data and change the mode or switch the controller on and off over Bluetooth LE. The first phone pairs without a code (it may just ask you to confirm); after that, other phones need the pairing code below. Bluetooth switches off with the WiFi when the car is parked (CAN sleep).

Update from a File

No internet needed. Upload one file from a release: the merged .bin updates everything - firmware and web UI - in one go. A bare firmware.bin or littlefs.bin also works if you only need one half; the module works out which it got. Settings and the learn table are kept. Firmware goes to the spare slot and rolls back by itself if the new build fails its safety checks. Releases are at github.com/Kile-Thomson/OpenHaldex-Edge.

Stay on this page and keep the module powered during the upload. It reboots when the update finishes and this page reloads itself.
